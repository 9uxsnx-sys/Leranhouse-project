# SSO Configuration

> Configure Single Sign-On (SSO) for your Koodook organization, allowing users to sign in with their existing Google, GitHub, Microsoft, or any custom OAuth 2.0 provider accounts.

## Overview

SSO (Single Sign-On) lets users authenticate using identity providers they already trust, reducing password fatigue and simplifying the login process. Koodook supports both common social login providers and generic OAuth 2.0 / OpenID Connect (OIDC) providers.

## Supported SSO Providers

| Provider       | Protocol       | User Info Endpoint                              | Notes                                    |
|----------------|----------------|-------------------------------------------------|------------------------------------------|
| Google         | OAuth 2.0 / OIDC | `https://www.googleapis.com/oauth2/v3/userinfo` | Most widely used; requires Google Cloud Console setup |
| GitHub         | OAuth 2.0      | `https://api.github.com/user`                   | Popular for developer-focused platforms  |
| Microsoft      | OAuth 2.0 / OIDC | `https://graph.microsoft.com/v1.0/me`         | Azure AD / Microsoft Entra ID integration |
| Custom OAuth   | OAuth 2.0 / OIDC | Configurable                                 | Generic support for any OIDC-compliant provider |

## Setup Instructions

### Prerequisites

Before configuring any SSO provider, you need:

- **Admin access** to the identity provider's developer console.
- **Organization admin access** in Koodook.

### General Steps (All Providers)

1. Go to **Admin Panel → Organization Settings → SSO**.
2. Click **Add Provider** and select the provider from the list.
3. Follow the provider-specific instructions below.
4. Save the configuration and test the connection before enabling it for all users.

---

### Google SSO Setup

1. Go to the [Google Cloud Console](https://console.cloud.google.com/).
2. Create a new project or select an existing one.
3. Navigate to **APIs & Services → Credentials**.
4. Click **Create Credentials → OAuth 2.0 Client ID**.
5. Set the **Application type** to **Web application**.
6. Add the following **Authorized redirect URI**:
   ```
   https://your-org.learnhouse.app/api/auth/callback/google
   ```
   Replace `your-org.learnhouse.app` with your actual domain.
7. Copy the **Client ID** and **Client Secret**.
8. In Koodook, paste these values into the corresponding fields.
9. Click **Save**.

### GitHub SSO Setup

1. Go to **GitHub Settings → Developer settings → OAuth Apps → New OAuth App**.
2. Fill in the application details:
   - **Application name**: Your Koodook organization name.
   - **Homepage URL**: Your organization's URL (e.g., `https://learn.yourorg.com`).
   - **Authorization callback URL**:
     ```
     https://your-org.learnhouse.app/api/auth/callback/github
     ```
3. Click **Register application**.
4. Copy the **Client ID** and generate a **Client Secret**.
5. In Koodook, paste these values.
6. Click **Save**.

### Microsoft SSO Setup

1. Go to the [Azure Portal](https://portal.azure.com/) → **Azure Active Directory → App registrations → New registration**.
2. Set the **Redirect URI** to:
   ```
   https://your-org.learnhouse.app/api/auth/callback/microsoft
   ```
3. Note the **Application (client) ID** — this is your Client ID.
4. Go to **Certificates & secrets → New client secret** to generate a Client Secret.
5. In Koodook, select **Microsoft** as the provider and enter the Client ID and Client Secret.
6. Optionally, configure the **Tenant ID** if you want to restrict sign-ins to a specific Azure AD tenant. Leave blank to allow any Microsoft account.

### Custom OAuth / OIDC Setup

For providers not listed above (e.g., GitLab, Facebook, LinkedIn, or a self-hosted Keycloak instance):

1. In Koodook, select **Custom OAuth** as the provider.
2. Configure the following fields:

   | Field                  | Description                                                  |
   |------------------------|--------------------------------------------------------------|
   | **Provider Name**      | A display name for the provider (e.g., "Company SSO")       |
   | **Client ID**          | The client ID from your provider                             |
   | **Client Secret**      | The client secret from your provider                         |
   | **Authorization URL**  | The OAuth authorization endpoint URL                         |
   | **Token URL**          | The OAuth token exchange endpoint URL                        |
   | **User Info URL**      | The endpoint that returns user profile information           |
   | **Scope**              | Space-separated scopes (e.g., `openid profile email`)        |
   | **Redirect URI**       | Auto-generated by Koodook; copy this to your provider        |

3. If the provider supports **OpenID Connect**, enable the **OIDC** toggle. Koodook will then use the `/.well-known/openid-configuration` discovery URL to auto-configure the remaining endpoints.

## Client ID and Secret Configuration

- **Client ID** is a public identifier that identifies your app to the provider. It is safe to share.
- **Client Secret** is a confidential credential. Treat it like a password:
  - Never share it publicly or commit it to version control.
  - Store it securely (e.g., a password manager).
  - Rotate the secret periodically (every 6–12 months is recommended).
- Koodook encrypts the client secret at rest. It is never displayed again after saving — you can only replace it with a new value.

## Redirect URI Setup

The redirect URI (also called callback URL) is the endpoint on your Koodook instance where the identity provider sends the user after authentication.

- The redirect URI format is:
  ```
  https://<your-domain>/api/auth/callback/<provider>
  ```
- For custom domains, use your custom domain in the redirect URI. If you have multiple domains, the redirect URI must match the domain the user is signing in from.
- Add **all possible redirect URIs** to your provider's configuration if you use multiple domains.

## Testing SSO Before Enabling

Koodook provides a **Test Mode** for SSO configurations:

1. After saving a provider configuration, click **Test Connection**.
2. A new browser tab opens and attempts the full SSO login flow.
3. If successful, you are redirected back to Koodook with a confirmation message showing the user info received from the provider.
4. If the test fails, an error message explains what went wrong (e.g., "Invalid client secret", "Redirect URI mismatch", "Scope not granted").
5. The test login creates a **temporary session** that is automatically cleaned up. It does not create a user account or affect any existing accounts.

### Enabling the Provider

Once testing succeeds:

1. Toggle the provider status from **Disabled** to **Enabled**.
2. Optionally, set the provider as **Default** — this adds a "Sign in with [Provider]" button to the login page.
3. You can enable multiple providers simultaneously. Users will see all enabled providers as login options.

### Disabling a Provider

- Toggle a provider to **Disabled** to immediately prevent new logins via that provider.
- Existing user sessions are **not** affected. Users who previously signed up with that provider can still log in via email/password if they have set one, or they will be locked out until another SSO method is enabled.

## Security Considerations

- **Email matching** — Koodook matches SSO users by their verified email address. If a user already has an account with the same email, they are linked to the existing account.
- **Account linking** — A user can link multiple SSO providers to a single Koodook account from their profile settings.
- **Domain restriction** — For Custom OAuth providers, you can restrict sign-ins to specific email domains (e.g., only `@yourcompany.com`). Users with other email domains will be rejected at login.
